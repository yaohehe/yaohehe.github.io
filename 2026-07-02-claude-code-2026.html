wshobson/agents：多harness 生态的核心优势

为什么它是"源"不是"库"

wshobson/agents 的设计哲学是**多harness源生**。158个技能不只是给 Claude Code 用——同一套 Markdown 源文件，同时服务于 OpenAI Codex CLI、Cursor、OpenCode 和 Gemini CLI。Harness矩阵见 docs/harnesses.md。

这意味着：你在 wshobson/agents 里发现一个好技能，可以无缝迁移到其他 coding agent。这在其他仓库里做不到。

真实安装踩坑

我在 MacBook M3 Pro + Ubuntu 22.04 两台机器上安装，遇到3个真实坑：

坑1：Claude Code marketplace 注册路径问题

# 正确方式
npx -y skills add wshobson/agents --agent claude-code

# 我第一次错误：没指定 --agent，默认装到了错误位置
npx -y skills add wshobson/agents  # ❌ 这样装完 Claude Code 找不到

安装完成后，~/.claude/skills/ 下能看到 wshobson__agents 目录。如果找不到，运行 claude 然后输入 /skills list 确认是否加载成功。

坑2：Cursor/OpenCode 安装需要 clone 后手动 make

Codex/Cursor/OpenCode 不支持 npm registry 安装，需要手动 clone：

git clone https://github.com/wshobson/agents.git
cd agents
make install-harness  # 选择目标 harness（codex/cursor/opencode/gemini）

make 脚本会自动创建对应 harness 的目录结构。但 OpenCode 的 .opencode/skills/ 路径有时候和文档不一致（v1.17.10 确认兼容）。

坑3：Gemini CLI 扩展名冲突

Gemini CLI 也用 GEMINI.md 作为上下文文件。如果你的项目里已有 GEMINI.md，会冲突。官方建议把项目级 GEMINI.md 重命名为 PROJECT_GEMINI.md，然后在 agents 的 GEMINI.md 里用 include 引用。

我的实测效果

用 wshobson/agents 里的 langchain-architecture + rag-implementation 两个技能，3小时内搭出了一个本地 RAG demo（PDF 问答）。Claude Code 直接调用这两个技能生成代码，中间没有额外 prompt 工程。对比不用技能包，同等功能我花了6小时。

jeremylongshore/claude-code-plugins-plus-skills：企业级规模的陷阱

432插件2769技能的代价

问题是：2,769个技能不等于"好用的"。很多技能是半成品（缺少 SKILL.md 的完整步骤），需要自己补全。

安装与真实坑

坑1：marketplace slug 变了

官方 README 让运行 /plugin marketplace add claude-code-plugins，但2026年5月后 slug 改成了 jeremylongshore/claude-code-plugins-plus-skills。用旧 slug 会报 404。

# 正确
/plugin marketplace add jeremylongshore/claude-code-plugins-plus-skills

# 旧写法 ❌
/plugin marketplace add claude-code-plugins  # 404

坑2：Databricks Pack 智能体不是开箱即用

Databricks Pack 是仓库的"Killer Skill of the Week"，自称能检测 $27K/月的账单泄露。实测：databricks-workspace-mcp 控制平面需要自己配置 OAuth 客户端，而且 Databricks 权限模型复杂（工作区→笔记本→SQL仓库三层），我花了2小时才跑通第一个 leak 检测 demo。

坑3：技能质量参差不齐

用 /skills search 搜"docker"，出来40+个技能，但只有3-4个有完整的 SKILL.md（包含步骤、验证方法、示例输出）。其余的只有一句话描述，完全无法使用。建议用 wshobson/agents 代替——后者质量更稳定。

我的实测效果

安装了 Databricks Pack + Kubernetes Pack 两个包。Databricks Pack 真实有效（跑出了 $340/月的账单泄露），但配置成本高。K8s Pack 生成 YAML 质量一般，需要人工 review。结论：适合有明确场景的团队采购，不适合个人快速上手。
