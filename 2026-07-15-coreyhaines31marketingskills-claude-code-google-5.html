💣 5 个真实踩坑与修复

踩坑 1：SEO 关键词聚类被强制应用，导致 7 篇文章内链互相打架

**现象**：跑 marketingskills/seo-content-brief 之后，Claude Code 自动给 7 篇相邻主题的文章（比如都是 WordPress wp-config 调优方向）添加了完全相同的核心关键词 "wp-config performance"，搜索引擎抓取后判定关键词堆砌（keyword cannibalization）。

**原因**：seo-content-brief skill 的默认行为是"每个 brief 列出 primary keyword + 12 个 supporting keywords"，但 brief 之间没有去重机制，多个 brief 跑出来就把同一组关键词分配给了相近主题。

修复：

# 1. 在 ~/.claude/skills/marketingskills/seo-content-brief/config.json 增加去重白名单
{
  "keyword_dedup_window_days": 14,
  "max_reuse_per_keyword": 2,
  "exclude_keywords_from_other_briefs": [
    "wp-config performance",
    "WordPress optimization"
  ]
}

# 2. 在每篇 brief 输出后强制做一次 sitemap.xml 关键词分布审计
claude "/skill marketingskills/seo-content-brief --topic='WordPress Object Cache' \
        --dedup-window=14 --max-keyword-reuse=2"

# 3. 用 ahrefs/semrush 数据反查是否有 cannibalization（实测：Search Console 7 天内同关键词多 URL 曝光是警报信号）

踩坑 2：Analytics 转化归因把"首页会话"全算给"上一篇文章"，CTA 点击率虚高 8 倍

**现象**：启用 marketingskills/analytics-conversion-attribution 之后，首页的 Clarity "会话来源" 100% 变成了"上一篇阅读的文章"，导致 CTA 按钮点击率从 1.2% 虚高到 9.6%。

原因：attribution skill 默认使用 last-click attribution model，把同一会话内所有内链点击归到最后一篇；但首页的会话其实来自外链+直接访问+搜索引擎，skill 把这些全归到"上一篇"是模型本身的偏差。

修复：

// ~/.claude/skills/marketingskills/analytics-conversion-attribution/config.js
module.exports = {
  attribution_model: 'position_based',  // 改成 40% 首次 / 40% 末次 / 20% 中间
  exclude_internal_traffic: true,        // 不再算站内互链
  lookback_window_days: 7,              // 7 天归因窗口
  home_page_exclude: true               // 首页不参与归因计算
};

跑完之后真实 CTA 点击率回到 1.4%，基本接近人工 GA4 数据。

踩坑 3：Copywriting skill 强加 CTA 文案，被读者吐槽"机器味太重"

**现象**：copywriting-page-cro 自动给每篇文章结尾加了 3 段 CTA 文案（"👉 立即注册 / 立即体验 / 立即领取"），模板风格强烈，读者评论 "一看就是 AI 生成的"。

**原因**：默认 cta_template 配置开启了 aggressive_cta: true，且所有 CTA 文本都来自模板库（不是基于文章上下文生成）。

修复：

// ~/.claude/skills/marketingskills/copywriting-page-cro/config.json
{
  "aggressive_cta": false,
  "cta_per_article_max": 1,                  // 每篇文章最多 1 段 CTA
  "use_context_aware_cta": true,             // 基于正文最后一段生成 CTA
  "forbidden_phrases": [
    "立即注册",
    "立即体验",
    "立即领取",
    "👉",
    "限时"
  ],
  "tone": "neutral_technical"                // 改成中性技术语气
}

修复后读者评论"机器味"的比例从 23% 降到 4%。

踩坑 4：skill 加载顺序冲突，Copywriting 与 SEO skill 同时跑会循环重写

**现象**：同时启用 seo-meta-optimizer + copywriting-page-cro 两个 skill 时，Claude Code 陷入循环：先 SEO 改了标题 → Copywriting 又改了 → SEO 又改回去 → Copywriting 再改，token 在 30 分钟内烧掉 65K，文章还是没改完。

**原因**：两个 skill 的 on_article_modified hook 互相触发，没有 cooldown 机制。

修复：

# 1. 给每个 skill 加 cooldown 配置
cat > ~/.claude/skills/marketingskills/.load-order.json << 'EOF'
{
  "skill_load_order": [
    "analytics-traffic-anomaly",
    "seo-content-brief",
    "seo-meta-optimizer",
    "copywriting-page-cro"
  ],
  "hook_cooldown_seconds": 300,
  "max_modify_rounds": 3
}
EOF

# 2. 单篇工作流明确分工：
#    Round 1: seo-content-brief（产出 brief）
#    Round 2: seo-meta-optimizer（产出 meta）
#    Round 3: copywriting-page-cro（产出 CTA）
#    不允许任何一轮触发其他 skill 的 hook

实测：单篇文章从 65K token 降到 18K token，速度从 30 分钟降到 4 分钟。

踩坑 5：跨站国际化失败，中文站文章自动翻译成"中文版英文"

**现象**：我两周前用 seo-content-refresher 给英文站刷新 2026 老文章时，skill 自动把内容回填到中文站，但生成的是"中式英语"（"你好世界" 翻译成 "hello world 你好"），完全不可用。我自己跑了一次后，发现中文站 11 篇文章里 7 篇被回填了 Chinglish 段，紧急回滚到 7 天前的 Git commit 才恢复。

**原因**：seo-content-refresher 没有 locale 隔离，混用 lang="zh-CN" 和 lang="en-US" 的 sitemap 条目。

修复：

  • 中文站: sitemap_zh.xml, 标记 lang="zh-CN"
  • 英文站: sitemap_en.xml, 标记 lang="en-US"
  • skill 跨站操作必须显式指定 --site=zh 或 --site=en
  • 默认禁止 cross-locale 内容回填
# 在 claude.md（项目根）里加 site 边界声明
cat > ./CLAUDE.md << 'EOF'
# 项目边界
EOF

# skill 调用时强制传参
claude "/skill marketingskills/seo-content-refresher \
        --article='2026-05-17-n8n-claude-code-mcp-integration' \
        --site=en \
        --locale=en-US"

修复后中英文两站内容完全隔离，Clarity 数据不再混算。

📝 我自己部署下来的两点额外感受

1. **默认配置不是给中文技术博客设计的**。我第一次跑 seo-content-brief 就发现，它推荐的 supporting keywords 全部是英文 SaaS 落地页套路（"best / top / cheap"），套到中文 wp-config 调优文章上完全不相关。我后来手动维护了一份 cn-tech-keywords-whitelist.json，把技术中文词的优先级手动拉高，才能跑出像样的 brief。

2. Clarity + GA4 双重验证才敢上线。我自己在每篇文章发布前都会用 Clarity 热图看一遍 CTA 的真实点击位置，对比 skill 给出的"应该点哪儿"，如果偏差超过 30% 就回滚 skill 改动，单靠 skill 输出数据是不可信的。

🛡️ 进阶配置（推荐）

1. **关闭自动重写**：config.json 里设 auto_rewrite: false，每次手动 /skill ... 触发

2. **审计日志**：开 audit_log: ~/.claude/logs/marketingskills.log，方便追溯哪个 skill 改了哪篇文章

3. Git 钩子：每篇文章自动 commit，diff 在 PR 评审时一目了然

4. **A/B 实验**：用 analytics-experiment-design 跑 14 天 CTA 文案 A/B test，再决定哪个版本上线
