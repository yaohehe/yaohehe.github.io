Why n8n with Langfuse, not LangSmith?

Trade-offs I weighed before committing:

  • **LangSmith Pro** — $39/seat/month, $117/mo for a 3-person team. Gorgeous traces, auto-eval, prompt hub. But two price hikes in 2026, and your data lives on LangChain's infrastructure.
  • **Helicone** — $20/mo Pro. Only sees the HTTP reverse-proxy layer, no n8n node-level trace.
  • **Langfuse self-hosted** — $5/mo VPS (4-core/8GB), 50k units/month free, no metering above that on self-hosted. Data fully owned.
  • **Arize Phoenix / LangWatch / Opik** — each has trade-offs; out of scope here.

I chose Langfuse v3 self-hosted: cost ceiling + data sovereignty + the n8n community has a working "Deep n8n Observability with OpenTelemetry + Langfuse" tutorial I could build on.

n8n workflow nodes (AI Agent / Anthropic / OpenAI / Ollama)
    ↓
n8n 1.88 built-in OpenTelemetry node (OTLP/gRPC exporter)

🚀 Deployment steps

Step 1: Deploy Langfuse v3 self-hosted

git clone https://github.com/langfuse/langfuse.git
cd langfuse
# v3 uses docker-compose.yml (NOT the v2 deprecated file)
cp .env.prod.example .env
# Edit these three required values
sed -i 's/POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=YOUR_SECURE_PG_PASS/' .env
sed -i 's/S3_ACCESS_KEY=.*/S3_ACCESS_KEY=langfuse-minio/' .env
sed -i 's/S3_SECRET_ACCESS_KEY=.*/S3_SECRET_ACCESS_KEY=YOUR_MINIO_PASS/' .env

docker compose up -d
# Wait until all services healthy (Postgres / ClickHouse / Redis / MinIO / Langfuse-Web / Langfuse-Worker)
docker compose ps

Open http://your-vps:3000, create your first project, copy the **Public Key** + **Secret Key** — you'll need them in Step 2.

Step 2: Deploy OpenTelemetry Collector

mkdir -p ~/otel-collector && cd ~/otel-collector
cat > otel-collector-config.yaml <<'YAML'
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 10s
    send_batch_size: 1024
  memory_limiter:
    check_interval: 1s
    limit_mib: 512

exporters:
  otlphttp/langfuse:
    endpoint: "http://langfuse-web:3000/api/public/otel/v1/traces"
    headers:
      Authorization: "Basic ${env:LANGFUSE_AUTH}"
    encoding: proto

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [otlphttp/langfuse]
YAML

# Basic auth = base64(public_key:secret_key)
export LANGFUSE_AUTH=$(echo -n "pk-lf-xxx:sk-lf-xxx" | base64 -w 0)
cat > docker-compose.yml <<'YAML'
version: '3.8'
services:
  otel-collector:
    image: otel/opentelemetry-collector-contrib:0.110.0
    command: ["--config=/etc/otelcol/config.yaml"]
    volumes:
      - ./otel-collector-config.yaml:/etc/otelcol/config.yaml:ro
    environment:
      - LANGFUSE_AUTH=${LANGFUSE_AUTH}
    ports:
      - "4317:4317"   # OTLP gRPC
      - "4318:4318"   # OTLP HTTP
    restart: unless-stopped
YAML

docker compose up -d
docker compose logs -f otel-collector
# "Everything is ready" = ready to receive

Step 3: Configure n8n's OpenTelemetry node

In n8n Web UI → Settings → Variables, add:

OTEL_EXPORTER_OTLP_ENDPOINT = http://host.docker.internal:4317
# If n8n and OTel Collector share a docker network, use the service name instead:
# OTEL_EXPORTER_OTLP_ENDPOINT = http://otel-collector:4317

Restart n8n so the env var takes effect:

cd ~/n8n-data && docker compose restart n8n

Step 4: Drop the OpenTelemetry node into your workflow

After any AI Agent / Anthropic / OpenAI / Ollama node, attach a built-in OpenTelemetry node:

  • **Source**: upstream node output
  • **Exporter**: OTLP/gRPC
  • **Endpoint**: `host.docker.internal:4317` (n8n in Docker reaching the host; if OTel Collector is on the same network, use `otel-collector:4317`)
  • **Service Name**: `n8n-workflow-prod`

Activate the workflow. Within 30 seconds, the Langfuse Tracing → Traces view should show live traces. Click any trace to see token / cost / latency breakdown.

💣 Pitfalls & troubleshooting

Trap 1: OTel Collector won't start — "bind: address already in use"

Cause: n8n itself opens an OTLP listener on 4317 by default. Two processes can't share the port.

**Fix**: Either disable n8n's built-in OTLP listener (N8N_DIAGNOSTICS_ENABLED=false), or move OTel Collector to 4327. **I prefer the latter**:

# otel-collector-config.yaml receivers.otlp.protocols.grpc.endpoint: 0.0.0.0:4327
sed -i 's/4317/4327/g' otel-collector-config.yaml
docker compose restart otel-collector

Then update the n8n endpoint to :4327.

Trap 2: Langfuse v3 returns 401 "Invalid credentials"

Cause: The Basic Auth base64 has a stray space or newline. The most common mistake:

# Wrong
export LANGFUSE_AUTH=$(echo -n "pk-lf-xxx: sk-lf-xxx" | base64)
# Right (no space in the input)
export LANGFUSE_AUTH=$(echo -n "pk-lf-xxx:sk-lf-xxx" | base64 -w 0)

-w 0 stops base64 from wrapping output — **this is the root cause of 90% of 401 errors**.

Trap 3: Traces reach Langfuse but every field is null

**Cause**: n8n's OpenTelemetry node emits OTel default semantics (service.name), but Langfuse v3 expects langfuse.session.id / langfuse.user.id / langfuse.tags. The OTel Collector doesn't remap these by default.

**Fix**: Add a transform processor in OTel Collector:

processors:
  transform:
    trace_statements:
      - context: span
        statements:
          - set(attributes["langfuse.session.id"], attributes["n8n.workflow.id"])
            where attributes["n8n.workflow.id"] != nil

Restart OTel Collector, trigger the workflow, and Langfuse will group traces by workflow session.

Trap 4: ClickHouse fails to start — "Cannot allocate memory"

Cause: Langfuse v3's default ClickHouse wants 4GB. Running n8n + Langfuse + OTel + ClickHouse on a 4-core/8GB VPS hits OOM.

**Fix**: Cap ClickHouse at 2GB in docker-compose.yml:

services:
  clickhouse:
    image: clickhouse/clickhouse-server:24.3
    deploy:
      resources:
        limits:
          memory: 2G

Also cap OTel Collector memory_limiter.limit_mib: 256 and Langfuse Worker at 1GB. **Keep total memory under 7GB** (leave 1GB for the OS).

Trap 5: OTel Collector drops a batch after restart

**Cause**: Default batch.timeout: 10s — spans still in memory during restart get discarded.

**Fix**: Bump timeout to 30s and add file_storage so spans survive a crash:

processors:
  batch:
    timeout: 30s
    send_batch_size: 2048
  file_storage:
    path: /var/lib/otelcol/storage
    timeout: 10s
service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch, file_storage]
      exporters: [otlphttp/langfuse]

📊 Token cost side-by-side (Anthropic / OpenAI / Ollama)

n8n's OpenTelemetry node auto-writes gen_ai.usage.input_tokens / gen_ai.usage.output_tokens / gen_ai.usage.total_tokens as OTel attributes. Langfuse v3's ingestion reads these and multiplies by the model price table you configure.

Price table lives at: Settings → Usage → Model pricing (self-hosted needs enable_pricing=true in .env). Set Anthropic Claude Sonnet 4.5 to $3/$15 per 1M tokens and every generation trace gets an auto-calculated cost field.

Cost-saving trick: local Ollama models (llama3.3 / qwen2.5-coder) recorded at $0. The trace view instantly shows which workflows hit cloud APIs vs. local models.
