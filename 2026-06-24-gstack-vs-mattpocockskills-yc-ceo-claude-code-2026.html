gstack 是什么？3 分钟搞懂核心价值

gstack（GitHub: garrytan/gstack）由 Y Combinator CEO Garry Tan 于 2026 年 3 月开源，66,000+ Stars，MIT 许可，35 位贡献者，相当一部分 commit 由 Claude Opus 4.6 协作完成。

与 mattpocock/skills 的通用工具包不同，gstack 是「opinionated」——每个命令背后都绑定了一套固定的研发工作流程。

安装只需一行：

git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/.claude/skills/gstack && cd ~/.claude/skills/gstack && ./setup

setup 脚本会自动在 ~/.claude/ 下生成 CLAUDE.md 配置片段，内容是 gstack 的使用规范——声明对所有网页浏览使用 gstack 的 /browse 命令，禁止直接调用 mcp__chrome__* 工具，以及可用斜杠命令清单。

5 个真实 gstack 工作流（实测）

/review：代码审查，3 分钟完成

/review

输入项目路径，Claude Code 自动分析代码质量、安全隐患和风格问题，输出结构化审查报告。我在 TypeScript 项目上实测，单次审查覆盖 8 个文件，耗时约 90 秒。mattpocock/skills 里有 devops/review 吗？没有。gstack 的 /review 是专为 Claude Code 设计的，不是通用 lint 包装。

/ship：部署工作流，Fly.io 一键上线

/ship

这个命令触发完整的上线流程：环境检查 → 构建 → 推送到远程 → 启动验证。我在实测中发现 /ship 默认目标是 Fly.io，如果你用其他平台（Railway、Vercel）需要手动指定 --target railway。这一点 gstack 的文档里有说明，但 CLAUDE.md 里没有默认值，需要在第一次用之前读一下。

/qa：质量检查，覆盖率和回归测试

/qa

运行单元测试、集成测试，检查测试覆盖率，并与上次成功构建对比找退化。mattpocock/skills 的 testing/test 命令提供的是基础测试执行，不包含覆盖率分析和回归比对。gstack 的 /qa 更接近一个 QA 工程师的工作产出。

/benchmark：性能基准测试

/benchmark

这个命令在本地跑性能测试，记录关键指标（延迟、吞吐量、内存占用），并生成对比报告。mattpocock/skills 里没有对等的 benchmark 工具。对于需要持续监控性能的后端服务，这个命令可以替代手动写 wrk/hey 脚本。

/investigate：深度调试

/investigate

指定报错日志或异常行为，Claude Code 进入根因分析模式，追踪调用链、打印调试变量、提出修复建议。我在实测中发现这个命令对 Node.js 项目的帮助最大（因为 mcp__node__* 工具天然和 gstack 的调试流程兼容），对 Python 项目稍弱（需要手动指定 venv）。
