CMR 与 SMR：差别到底在哪

这是本文的核心，也是 2020 年那场诉讼的核心。

CMR（常规磁记录）的每条磁道独立并排，写一个扇区只写那一个扇区，互不干扰。SMR（叠瓦式磁记录）把磁道像瓦片一样叠起来以提高密度，代价是改写一个扇区时必须重写相邻的整条磁道带（write amplification，写放大）。

日常顺序读写时，SMR 差别不大。但 NAS 场景的核心动作恰恰是最不擅长的那一种：

  • 写入是碎片化的（时Taskshed 备份、Plex 元数据、照片索引）
  • 重建需要全盘连续读 + 大量校验运算
  • RAID 校验和计算本身就是密集的小块写

独立测试复现的结果是：SMR 盘的 RAID 重建从 12–24 小时拖到 48–72 小时，在 ZFS 上尤其明显。这不是理论风险，是能复现的数字。

而在重建拖长的窗口里，阵列处于降级状态，第二块盘出问题时就是数据全丢。我的 84 小时和别人的 48–72 小时是同一个机制的不同长度。

还有一个更隐蔽的杀手，术语叫 TLER（限时错误恢复），NAS 盘的固件特性。硬盘遇到坏扇区时，桌面盘的固件会反复重试 7–15 秒甚至 30 秒以上，RAID 控制器在超时后认为「这块盘死了」，直接把它踢出阵列、触发重建。NAS 盘把重试时间限制在 7 秒以内，宁可报错也不让阵列把自己踢掉。

这就是为什么「把桌面盘拿来组 NAS 省点钱」是个陷阱：桌面盘的负载评级只有 55TB/年（BarraCuda），NAS 盘是 180TB/年；坏扇区处理策略不同；而且桌面盘跑出保保修会被拒。

怎么确认手上这块盘是 CMR 还是 SMR

按可靠度从高到低：

1. 看型号，不是看系列名。 把盘上的型号抄下来（Seagate 是 ST8000VN004 这种，WD 是 WD80EFPX 这种），去厂商规格页比对。厂商在 2020 年之后都开始在规格页标注 CMR / Conventional Magnetic Recording。

2. 规格页没写 CMR，就当未验证。 这是我给自己定的硬规则——没标注就是没标注，不靠社区表格单方面定案。

3. 别指望 CrystalDiskInfo 告诉你。 它能给你型号、转速、SMART 数据，但这些字段都不足以判定 CMR 或 SMR。我见过太多人拿着 CrystalDiskInfo 的截图来问「这个是不是 SMR」，答案是截图里没有这个信息。

4. 型号里有一个真实的坑，以我手上这块 IronWolf 8TB 为例：Amazon 商品标题里写的是「5,400 RPM」，但型号 ST8000VN004 实际是 7200 RPM，5400 RPM 的是 ST8000VN002。这两个型号只差一位，价格和噪音完全不同。买之前必须核对型号，不能只看标题里的转速数字。

故障排除：五个我实际遇到过的报错

报错一：`zpool import -f ` 报 `cannot import '': I/O error`

这不一定是最坏消息。 我第一次遇到时以为是元数据损坏，准备走付费恢复。实际原因是我给日志盘单独划了一块虚拟磁盘做 SLOG，机器重装后那个盘没了，池导入时找不到它，ZFS 拒绝导入整个池——虽然真正的主数据盘一块都没坏。

排查顺序（先确认池是否在另一台主机上挂着，这一步别跳过）：

zpool status -v
zpool events -v | tail -50
lsblk -o SERIAL,WWN,MODEL,SIZE

看 zpool status 里有没有 logs UNAVAIL 或 cache UNAVAIL。如果有，用 -m 参数容忍缺失的日志/缓存设备：

zpool import -f -m 
zpool remove  <缺失设备ID>

导入后跑一次 scrub 确认数据完整。如果池子报不出任何错误信息、你又不确定盘里有什么，先只读导入：zpool import -o readonly=on ，把数据拷出来再想办法。只读导入不写任何新元数据，是这一步能承受的最大风险。

绝对不要做的事：没看懂报错就 zpool destroy；对疑似坏盘执行 dd if=/dev/zero；同时在两台主机上导入同一个池。

报错二：开机卡在 `Starting ix-zfs.service - Import ZFS pools...` 超过 15 分钟

TrueNAS SCALE 停在导入进度条，日志显示 ix-zfs.service start running (53s / 15min 26s)。

这不是系统卡死，是 ZFS 在等一块不响应的盘。 ZFS 宁可一直等也不愿冒险写坏数据。触发原因通常是某块盘进入「半死」状态（超时但没彻底掉线），或者上次非正常断电留下了脏状态。

处置步骤：

1. 这次开机先等满 10–15 分钟，观察盘位指示灯是否还在闪。有活动就说明在推进

2. 不动就重启，从 GRUB 进 Advanced options → TrueNAS SCALE → Recovery Mode，或启动时按 Esc 进 Drop to root shell

3. 在 root shell 里先做无写入探测：zpool import，以及 dmesg | grep -Ei "ata|sas|scsi|error|timeout|reset"

4. 看到 I/O error、link reset、device offline、failed command 就是盘或线的问题。SATA 数据线老化、电源分线器故障、盘体慢死是三大常见原因，HBA 固件问题排第四

5. 确认已备份的前提下，断电拔掉一块盘，重启试导入，逐个定位。RAIDZ2 允许缺两块盘，所以诊断过程本身是安全的

6. 成功导入后立刻 zpool status -v 加 zpool scrub，并用 smartctl -a /dev/sdX 检查替换下来的那块盘

我在一次 RAIDZ2 故障里用这套方法逐块排除，定位到是一根劣质 SATA 线，不是盘——换线后阵列直接完整导入，省下了一整块 8TB 的钱。所以出问题时先怀疑线缆，不是先怀疑盘。

报错三：`zpool scrub` 后 resilver 进度条几乎不动 / 重建时间远超预期

SMR 盘在阵列里最典型的症状就是这个。 你以为是网络慢或盘坏了，实际是写放大在拖后腿。

先确认记录方式：smartctl -i /dev/sdX | grep -i model，再按上文方法核对型号。如果发现是 SMR，处置有两条路：

  • 短期：接受长时间重建，但必须确保阵列有冗余（RAID5 至少 1 块，RAIDZ2 至少 2 块冗余），并且这段时间不要往里写数据。任何一块盘出问题立刻停手
  • 根本：把 SMR 盘换成 CMR 盘重建。我实测同一阵列从 SMR 换 CMR，重建时间从 84 小时降到 19 小时，相差四倍多

另外提醒：resilver 期间盘会很热，别中途断电。也别为了「加速」去跑 zpool scrub，两者会互相拖慢。

报错四：`smartctl -H /dev/sdX` 显示 `PASSED!`，但盘明显有异响

PASSED! 不是健康证明，这是 SMART 最常见的误判来源。 它的判定逻辑仅仅是「没有任何 pre-fail 属性低于阈值」，而厂商设的阈值通常高到几乎不可能被触发。所以大批明显在死的盘照样报 PASSED。

必须自己看原始值的五个属性（这也是 Backblaze 长期只认这五个的原因）：

smartctl -A /dev/sdX | grep -E "Reallocated|Reported_Uncorrect|Command_Timeout|Current_Pending|Offline_Uncorrect"
属性ID判据
Reallocated_Sector_Count5任何非零增长都该换盘，它就是重映射扇区数
Reported_Uncorrect187大于 0 就换，ECC 修不好的读错误，Backblaze 见到即排修
Command_Timeout188命令超时次数，持续增长说明固件在挣扎
Current_Pending_Sector197待定扇区，坏但还没重映射
Offline_Uncorrectable198离线扫描都无法纠正

其中 187 一旦大于 0 基本就是判死刑，Backblaze 的车队数据显示 187 长期为 0 的盘几乎不会坏，一出现就直接进替换队列。

还要会读这些字段的正常波动：184 End-to-End Error 是硬盘缓存到控制器的奇偶校验错误，持续增长才要处理；190 和 194 两个温度字段数值不同，一个测环境气流一个测盘体。

如果盘挂在 USB 硬盘盒里，smartctl 可能读不到——USB 桥接芯片不一定翻译 SMART 命令，要加 -d sat 参数。硬件 RAID 卡后面的盘不是块设备，得用 -d megaraid,N 或 -d cciss,N 直连控制器。虚拟磁盘、virtio、云盘都读不出 SMART，要监控就得回到宿主机。

报错五：RAID 阵列无故掉盘，控制器日志里是一堆超时

如果阵列里混了桌面盘，先怀疑 TLER 缺失。 桌面盘遇到坏扇区会重试 7–15 秒甚至更久，RAID 控制器超时后认为它已死、把它踢出阵列并触发重建；NAS 盘的 TLER 把重试限制在 7 秒内，宁可报错也不踢盘。这就是「没人为坏道付出代价，但整阵列跟着遭殃」的机制。

处置：

1. 确认每块盘的固件与工作负载。桌面线典型是 55TB/年，NAS 线 180TB/年，Pro 线 550TB/年。桌面盘跑出保时保修会被拒

2. 确认型号是否 CMR（方法见上文）

3. 别做混插品牌实验。控制器不关心品牌，只读写裸块，所以混插技术上可行，但 RPM 不同会让整阵列降到最慢那块的速度，缓存不同也会互相影响

4. 换盘时优先换同型号同容量，别拿 Pro 盘替换标准盘凑数

FAQ

Q：CMR 和 SMR 我怎么在买之前就知道？

只能靠型号查规格页，没有别的可靠办法。规格页没标CMR 就当未验证。别用 CrystalDiskInfo 判断，它没有这个字段。系列名不算证据——Seagate 和 WD 都在同一系列内部按容量混了 CMR 和 SMR。

Q：2026 年该不该等硬盘降价？

趋势上没有支持等待的信号。公开数据显示西部数据产能售罄至 2026 年底、希捷近线产能全部分配，且没有任何可引用的公开信息指向 2027 年前消费级降价。但短期内价格波动可能很剧烈（我记录到 48 小时 +21%），所以「按真实需求买、把盘位留空、等 $/TB 数字变好再加」比「一次性囤满」更稳妥。

Q：二手盘或者翻新的企业盘划算吗？

数据中心的退役盘在二手市场确实能拿到更低的 $/TB，也有 5 年保的正规翻新件。但如果你的盘要放进 RAID 阵列，我建议全新盘——二手盘的通电时长和坏道分布不可知，而你需要一个能扛住重建压力的成员。二手或翻新盘更适合放在独立的离线冷备位置。

Q：笔记本能直接接 2.5 寸盘吗？

可以，但速度受限。笔记本的 USB 口通常只有 USB 3.0（5 Gbps），实际顺序读落在 150–200MB/s 区间。真正被限制的是笔记本的随机写能力——归档顺序读没问题，跑数据库或虚拟机磁盘就不合适。

Q：NAS 一定要上 Pro 盘吗？

不用。550TB/年工作负载是给多用户高强度写入的商用阵列设计的，家庭 2–4 盘位、主要是备份和照片归档的场景，180TB/年足够。差别主要在保期（5 年 vs 3 年）、负载评级和噪音功耗上。

Q：怎么把退役的旧盘安全处理掉？

先跑一遍完整自检确认状态：smartctl -t long /dev/sdX，等测试跑完再看 5/187/197/198 四个原始值。健康的话放进 USB 硬盘盒做归档盘，不要直接拼进现役阵列——通电时长和累积坏道都是未知变量。
