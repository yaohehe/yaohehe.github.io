HStudy 家庭学习 App：积分只在家长批准后到账

HStudyKotlin Multiplatform家庭学习

HStudy 是我做的一款家庭学习 App。它不负责出题，也不负责讲课，管的是家长和孩子之间那句「说好了做完就加分」的口头约定：孩子打卡、家长审批、积分入账，三件事有先后，也有据可查。Android 和 iOS 共用一套 Kotlin 代码，界面中英文随时切换，数据留在本机。

它现在是 v3.3.1，免费，没有内购。下面按「它解决什么麻烦」「六个模块怎么分工」「积分为什么可信」「技术上做了哪些取舍」讲一遍，最后是安装升级会卡住的地方和隐私说明。

先说 HStudy 是什么

HStudy 在同一台设备上提供家长和孩子两种身份，也可以两台设备配对使用。家长一侧负责配置：建任务、排日程、定奖励、批积分；孩子一侧负责执行：打卡、专注、记错题、花积分。两边看到的是同一个本地数据库，没有云端账号，也不依赖网络。

这个定位带来的第一个后果是安装方式：它没有上架应用商店，安装包只在 GitHub Releases 发布。第二个后果是数据边界很清楚——所有任务标题、错题内容、积分记录都在设备自己的数据库里，换手机靠导出备份，不是靠登录。

它冲着三个具体麻烦来

多数家庭学习 App 不是功能太少，而是三件事站不住。

批的是什么，家长不知道。 孩子点一下「完成」，分就到手了，家长事后才发现那项任务根本没做。审批在这里不是形式，而是唯一的入账闸门。

账对不上。 积分记成一个数字，改一次、撤一次，过两周谁也说不清余额是怎么来的。HStudy 的做法是不允许直接改数字，余额永远由记录加总得出。

错题记了就沉底。 错题本填满之后没人再翻，下次考试还是同一道题。复习要有排期、有提醒、有主动回忆，否则只是抄写。

六个模块各管什么

任务与审批。 家长建任务并设定基础分与难度系数，孩子完成后提交打卡。任务卡上直接显示五种状态：待审、已到账、已拒绝、已取消、已撤销。拒绝之后孩子可以重新打卡；家长误点「通过」也有出口，撤回会追加一条反向记录冲抵，而不是把原记录删掉。

专注。 番茄钟带呼吸引导和休息循环，另有舒尔特方格训练。番茄钟真正的难点不是计时，是中断：切页面、息屏、甚至进程被系统杀掉，回来都得接着算并补上结算，否则孩子白坐二十分钟。屏幕在计时期间保持常亮。

错题复习。 错题按学科与错因分类，按间隔重复排期，每天有提醒，复习走主动回忆流程（先想再看）。做对、仅复习、举一反三分别计 3 分、1 分、3 分，同样要家长审批。

奖励。 每日幸运抽奖、宠物照料、心愿存钱罐、奖励商店、成就徽章。心愿存钱罐的存入和退还走同一条积分流水，删掉心愿时已存的分数原路退回，不会凭空消失。

报表。 每周学习周报、专注效率报表、成长报告，把打卡次数、专注时长、复习量放在一起看，而不是只给家长一个总分。

家庭协作。 布置任务、排日程（带闹钟提醒）、21 天习惯挑战、每日目标；两台设备可在局域网内配对，家长配置支持导出与导入，也可以做完整备份和恢复。

积分账本：五条不变量

这套积分系统最容易被低估。它没有「余额」这个可以直接写的字段，只有一本只增不改的记录，余额是加总出来的。整件事由五条规则约束：

打卡不计分。 打卡只写完成记录和一条待审申请，绝不动余额。这一条听起来理所当然，但早期版本里习惯打卡、布置任务、每日目标三条路径都直接调了加分函数，绕过了审批。

一业务一生效申请。 用业务键（形如「任务 12 在 11 月 22 日」）约束：同一件事同时最多一条待审、最多一条已通过。

审批幂等。 只有待审状态能翻成已通过并计分，重复点「通过」不会重复加分。这在网络卡顿、家长手抖连点时是刚需。

撤销对称。 没批过的撤销是取消，本来就没分；批过的撤销追加一条反向记录冲抵，状态转为已撤销，徽章会如实翻过去。

账本只增不改。 积分记录只增不删，余额等于所有记录之和。代价是不能「帮他改一下」，收益是任何一笔都能追溯到审批人、时间和业务键。

五条规则里有四条是并发和幂等的问题，光靠代码审查看不出来。我实际把积分不变量写成了回归测试，用真数据库跑「重复审批」「并发领取」「撤销后再打卡」这些路径。原因很简单：测试全绿不等于逻辑正确，尤其是断言只覆盖正常路径的时候——这一点我在单元测试静默失效的那篇笔记里踩过一次。

一套代码两个平台：KMP 重写的取舍

HStudy 原来是一个纯 Android 项目，v3.0.0 起重写成 Kotlin Multiplatform 加 Compose Multiplatform。现在业务逻辑和界面都在共享层，commonMain 里有 178 个 Kotlin 文件、四十多个页面；Android 和 iOS 各自只保留必须落到平台的部分：通知与闹钟、相机、文件分享、设备发现。

这个改动的收益是界面只写一遍。代价在边角：iOS 上有些通知属性没法从 Kotlin 侧赋值，只能写一层 Objective-C 桥接；相机和分享要各写一套适配。凡是说「一套代码两端通吃」的项目，收益都在主干上，成本都在这些边角里。

数据层没跟着重写。数据库还是原地不动，Room schema 现在到 v13，带 v1 到 v13 的完整迁移链，升级时保留全部数据，迁移前自动备份。数据库迁移是我最不放心的部分——Alembic 那篇实测里，autogenerate 漏掉的东西足以让一次「成功」的迁移丢字段，所以这里每次都配了迁移校验测试。

质量闸门是 302 个单元测试加双平台 CI：Android 在 Ubuntu runner 上构建测试，iOS 在 macOS runner 上出模拟器包。这套测试比 v3.3.0 的 252 条多了约 20%。

双语不是外挂一层翻译

中英文是设计进去的，不是后加的。文案按页面分成 47 张表，每条都是一个有类型的字段——漏一条英文会直接编译失败，而不是运行时悄悄退回中文。这个选择很笨，但比「上线后发现有半屏中文」便宜。

切换语言不需要重启：偏好存在本地，界面跟着重组；通知标题、周报、日程提醒在发出那一刻取词，所以也跟随当前语言。系统语言是默认值，家长可以在设置里覆盖。

有一类内容不翻译：孩子自己输入的任务名、错题内容、心愿名称，原样显示。

安装与升级：三个会卡住的地方

安装包在 GitHub Releases 页，Android 是已签名的 APK，v3.3.1 大约 21.7 MB，支持 Android 8.0 及以上。三个已知的卡点：

签名不一致，装不上。 如果设备上装过调试版或其他签名的版本，覆盖安装会失败，系统提示应用未安装，adb 里报 INSTALL_FAILED_UPDATE_INCOMPATIBLE。解决办法是先卸载再装——但卸载会清数据，所以先导出备份。

Android 8.x 的老版本升不上去。 v3.2.1 做过一次签名密钥轮换，把 v2 的调试密钥换成正式密钥，Android 9 以上靠轮换授权可以直接覆盖升级，数据保留。例外是 Android 8.x 且已经装了 v3.0.0 到 v3.2.0 的设备：这一档没法直接升，需要导出备份、卸载、安装、再恢复。

iOS 只能跑模拟器。 发布的是未签名的模拟器包，装到真机需要 Apple Developer Program 会员和签名证书。这一点短期内不会变，别指望下载就能装。

备份这一步值得单独说：SQLite 的备份不是复制文件那么简单，热备出来的副本可能能打开、却少了一截数据。我在热备份丢 14500 行的那次实测之后，给自己定了个规矩——备份完必须校验行数，不是看到文件生成就算数。

隐私：发了什么，没发什么

HStudy 用 Google Analytics for Firebase 统计功能使用情况，用来判断哪些模块真被用、哪些建了没人碰。家长设置里有「分享使用数据」开关，默认开启，关掉立即停止上报，重启后仍是关闭，关闭期间的数据不会补发。

会发送的是界面路由名、功能使用次数、是否排了提醒、语言切换、备份导出、配对完成，加上 SDK 自带的设备型号、系统版本、国家、时区。不会发送姓名、任务标题、错题内容、积分数值、学习时长、设备名、配对码，以及任何自由文本。

需要说清楚一点：Firebase 会分配一个稳定的伪匿名标识，它能关联同一台设备上的多次使用。「匿名」在这里的准确含义是伪匿名，不是不可关联。如果这一点对你是硬要求，那就把开关关掉，功能不受影响。

适合谁用

适合想要一个不联网也能用、数据在自己手机上的家庭学习工具的家长；适合已经在用纸质积分表或 Excel、但账目开始对不上的家庭；也适合想看看 Kotlin Multiplatform 在真实项目里能走到哪一步的开发者。

可能不适合需要多设备云端实时同步、或者多个家长账号协作管理的家庭——HStudy 目前是本机数据库加局域网配对加文件备份，没有账号体系。也不适合希望从应用商店一键安装的人。

常见问题

Q：孩子会不会自己偷改积分？ 没有直接改数字的入口，所有加分都要走审批记录，余额是加总出来的。家长还可以在审批历史里撤回误批。

Q：换手机怎么迁移？ 用完整备份导出再导入。Android 上换机也能用系统备份，但因为签名轮换，跨大版本升级时建议手动导出一份。

Q：没有网络能用吗？ 核心功能全部本地，打卡、审批、专注、错题、奖励都不需要联网。只有统计上报会用到网络，且可以关闭。

Q：支持几台设备？ 目前是局域网配对加备份文件，适合一个家庭两台设备，不是多端云同步。

Q：会收费吗？ 现在是免费，也没有内购和付费墙。作者接受 GitHub Sponsors 支持，纯自愿。

最后

HStudy 解决的不是「怎么让孩子多学」这种大问题，而是「说好的奖励怎么兑现」这种小问题。小问题一旦开始扯皮，整套激励就失效了，所以这里选了最笨的做法：积分不能直接改，一切都留记录。
