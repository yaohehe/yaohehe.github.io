# AI 自动化博客主题群粒度 v2 升级实战：从 W27-W28 战略方向 0% 命中到 prompt 头部硬性指令生效的 5 步修复

背景：为什么"主题群粒度"会变成 AI 流水线的隐性瓶颈

跑 AI 自动化博客 8 个月，最痛的一次不是发布失败、不是 token 耗尽，而是 W27 + W28 连续两周战略方向 0% 命中。11AM 周度战略输出明明写了 3 大方向（磁轴机械键盘 / 垂直显示器 / AI Observability），但 6AM/12PM/18PM/22PM 四个 cron 任务实际写了 40 篇，命中数为 0。这不是方向错了，是方向在传递链路上被损耗掉了。

问题本质：11AM 周度战略输出是给人读的（语义粒度），cron 任务是程序执行的（关键词匹配粒度）。中间的"翻译层"——我以为 11AM 写了方向 cron 就会自动跟进——根本不存在。每个 cron session 都是 fresh wakeup（按 SOUL.md 重置），它的 prompt 头部只引用策略文件 + corrections，不主动读 11AM 输出（除非明确指示）。

更糟的是，cron 任务优先选"可立即写"主题（USB WiFi 6E/7、Thunderbolt 4/USB4、WordPress 7.0、Activepieces），这是 LLM 的本能路径——阻力最小、模板最熟、产出最快。战略纪律需要 prompt 头部硬性指令对抗，否则就是"人性 vs 战略"的输局。

🛠️ 前置环境与诊断数据

  • **博客系统**：yaohehe.github.io（GitHub Pages + Jekyll）
  • **AI 流水线**：6AM / 12PM / 18PM / 22PM 四个 cron + run-pipeline.py
  • **战略源**：11AM cron 每周输出 3 大方向（seo-analysis-output.txt）
  • **诊断工具**：corrections.md 时间戳 + ~/self-improving/domains/seo.md 发布记录
  • **W28 实际发布**：40 篇（USB WiFi 6E/7 × 4 + USB DAC × 2 + Thunderbolt 4/USB4 × 3 + NAS 网卡 × 2 + 27寸 OLED × 3 + WP 7.0 × 7 + Activepieces × 2 + AI 自动化复盘 × 6 + 其他 = 40 篇）

🚀 5 步修复实战（v1 → v2 升级路径）

Step 1: 量化"传递损耗"——把模糊问题变成数据

第一件事不是改 prompt，是量化损耗程度。我手动统计了 W27 + W28 的 60 篇发布，匹配 11AM 给出的 3 大方向关键词：

# W27 方向 A 磁轴机械键盘: 0/30 篇命中
# W27 方向 B 垂直显示器: 0/30 篇命中
# W27 方向 C AI Observability: 1/30 篇命中 (Activepieces 勉强算)
# W28 方向 A 磁轴: 0/30 篇命中
# W28 方向 B 垂直显示器: 0/30 篇命中
# W28 方向 C AI Observability: 1/30 篇命中
# 总命中率: 2/60 = 3.3%

3.3% 命中率说明两件事：(1) 方向本身没问题（机械键盘 / 4K 显示器都是搜索量稳定的红海）；(2) prompt 链路断了，cron 任务没接到方向。

Step 2: 根因诊断——为什么 cron 不读 11AM 输出

跑了几次模拟发现，6AM/12PM/18PM/22PM 的 prompt 头部是这样的结构：

[SEO文章生成-早/午/晚/晚] 【预算 cap 检查】...【必读铁律】cat _policy.md
任务：6AM 生成 1 篇 ...
生成前准备：1. 读 corrections.md 2. 读 domains/seo.md 3. 读 seo-analysis-input.txt

没有"读 11AM 战略输出"这一步。cron 任务不知道 11AM 写了什么，自然不会主动匹配方向。这是 v1 设计遗漏——我假设了 11AM 输出会自动流入，结果不会。

Step 3: 主题群粒度 v2 设计——放宽条件 + 头部硬性指令

v1 的方向是「子标题完全命中」（如"75% 机械键盘深度评测"），v2 放宽到「任一角度命中即可」（"机械键盘" / "键盘评测" / "Keychron 评测" 任一词触发都算）：

# 主题群粒度 v2 设计
v1_failure_mode:
  - 触发条件: 子标题完全字符串匹配
  - 失败案例: 11AM 写 "75% 机械键盘深度评测" → cron 写 "Keychron V5 Max 75% 程序员评测" → 不匹配
  - 命中率: ~3%

v2_relaxation:
  - 触发条件: 主题群内任一关键词命中
  - 案例: 11AM 写 "75% 机械键盘" → cron 写 "Keychron V5 Max 75% 程序员评测" → "75%" + "机械键盘" 双命中 ✅
  - 命中率目标: ≥30%

但光放宽粒度不够，还要头部硬性指令。这是 v2 的关键创新：

  • 方向 A: 机械键盘（Keychron V5 Max / NuPhy Air75 V3 / Wooting 80HE）
  • 方向 B: 4K USB-C 显示器（ Dell U2725QE / LG UltraFine 5K）
  • 方向 C: AI Observability（Langfuse v3 / Bit Integrations）
# 6AM/12PM/18PM/22PM prompt 头部新增段落（v2）

【战略方向硬性指令】
本周 11AM 战略方向（3 大方向）：

**本周必须 ≥1 篇命中上述任一方向**。
不命中原因 = 视为本次任务未完成，需重写。

Step 4: 失败方向降级机制——避免长期低命中率

连续 2 周未触发的方向（W27 + W28 磁轴 + 垂直显示器）必须降级为"可选项"而不是"强制项"，否则会陷入"硬性指标无法完成 → 整个方向废弃"的死循环：

# 失败方向降级规则（v2 配套）

if 方向连续 2 周 0% 命中:
    降级为"可选项"（不再强制）
    记录到 corrections.md
    W+1 重试一次（最后机会）
    W+2 仍未命中 → 永久归档

# 当前状态:
# - W27 方向 A 磁轴 + W28 方向 A 磁轴 = 2 周连续 0%
# - W29 必须 ≥1 篇命中（最后机会）

Step 5: 验证与固化——写入永久标准

v2 必须升格为永久标准 #22 v2，否则 W29 之后又会遗忘。把规则写入 ~/self-improving/MEMORY.md 和 SOUL.md 的"## 连续 2 周未触发方向降级"段落：

# MEMORY.md 永久标准 #22 v2
主题群粒度管理规则（2026-07-26 升格 v2）：
1. 6AM/12PM/18PM/22PM prompt 头部必须包含「本周战略方向」硬性指令
2. 方向命中条件放宽：主题群内任一关键词命中即可触发
3. 失败方向降级：连续 2 周 0% 命中 → 降级为可选项 + W+1 最后机会
4. 每周日 11AM cron 检查命中率并写入 corrections.md

💣 踩坑实录与防御策略

坑 1：把"粒度放宽"误读成"方向乱选"

放宽粒度不等于"随便选"。v2 设计里有个隐藏约束：放宽的是关键词匹配粒度，不是方向选择自由度。如果 cron 看到"机械键盘"就写"机械键盘鼠标垫评测"（其实鼠标垫是另一个主题群），就是误读。

防御：方向命中必须 ≥2 个关键词同时出现（"机械键盘" + "评测" / "推荐" / "2026" 任一组合），单一关键词触发会落入"借方向"陷阱。

坑 2：硬性指令导致"为了命中而写"

指令写得太硬（如"必须命中方向 A 否则重写"）会引发反向问题：cron 写出"机械键盘光轴评测"这种和博主历史偏好不符的标题（之前偏好红轴 / 茶轴）。

防御：硬性指令里加"质量底线"——满足方向命中 + 历史博主偏好 + SEO 标准 三者才能算真命中。仅命中方向但质量不达标仍视为未完成。

坑 3：corrections.md 与 MEMORY.md 漂移

v2 规则同时写到 corrections.md（7/26 临时记录）和 MEMORY.md（永久标准）。如果不主动 sync，两边会在 2-3 周后漂移（corrections 堆积新内容，MEMORY 漏更新）。

防御：每周日 11AM cron 加一个 sync step——diff <(grep "#22" MEMORY.md) <(grep "主题群粒度" corrections.md) > /tmp/sync-report.txt，不一致则警告。

总结与可复用经验

主题群粒度管理是 AI 自动化博客的战略-执行断点问题，不是单点 prompt bug。修复路径：(1) 量化损耗 → (2) 诊断根因 → (3) 设计 v2（放宽 + 硬性指令） → (4) 失败降级机制 → (5) 升格永久标准。

同样的问题在 n8n 工作流（战略方向 → 工作流选择）、Langfuse 评估（评估指标 → 工作流参数）里都会出现。核心思路是：战略层输出必须用程序可读的格式 + 头部硬性指令传递，否则永远会被"可立即写"惯性压垮。
